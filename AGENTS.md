# Portfolio Repository Instructions

## Required behavior

- Read the entire repository before beginning work so you understand the existing application, configuration, and project conventions.
- Do not add, modify, delete, rename, commit, or push any files unless the user explicitly asks you to do so.
- When the user authorizes a change, explain every file changed, what changed, and why the change was necessary in the final response.

## Protect existing work

- Treat uncommitted changes as user work. Do not overwrite, revert, discard, or reformat unrelated changes without explicitly stating that you have done so and to what files.
- Do not change GitHub, Vercel, domain, deployment, environment-variable, or repository settings unless the user explicitly requests that specific action.

## Implementation and verification

- This is a Next.js, TypeScript, Tailwind CSS, and Framer Motion portfolio application. Preserve its established component structure and visual style unless the user requests a redesign.
- For authorized code changes, run relevant, non-destructive validation (such as linting or a production build) when practical, and report the result.
